### 小算子写完后，应该继续优化哪里

你已经知道融合 Softmax 如何减少中间读写。但在真实模型中，最值得投入的热点未必是孤立的 Softmax。它可能是整个 Attention，也可能是量化矩阵乘法或 MoE 通信。

本课把三个问题连起来：FlashAttention 如何避免巨大的中间写回；量化为何既改变存储也改变数值；一个局部优化最多能给整个系统带来多少收益。它们共同帮助你选择下一步工作。

### 标准 Attention 的中间矩阵为什么昂贵

概念公式是 `softmax(QKᵀ/√d)V`。序列长度为 T 时，分数和权重有 T×T 项。即使输入向量维度不变，T 翻倍，配对数量也约变为四倍。

直接实现可能先把分数写到 HBM，再读出来做 Softmax，再写权重，再读它与 V 相乘。这些中间流量可能很大。

一个关键观察是：我们最终需要的是加权后的输出，并不一定要把所有中间权重完整保存到 HBM。只要能逐块更新归一化和累积结果，就有机会减少 IO。FlashAttention 的核心方向就是这种分块和片上复用，而不是把标准 dense attention 的所有配对计算变成线性。

### 为什么不能把每个块单独 Softmax 再相加

考虑只有两个分数 `[0,0]`、对应 values `[2,4]` 的情况。全局 Softmax 权重是 `[0.5,0.5]`，结果为 3。

若把每个分数单独做 Softmax，每块只有一项，权重都变成 1，直接相加会得到 6。问题出在每块的归一化分母不同。分块计算必须保留足够统计量，才能恢复全局归一化。

对于一个 query，可以维护运行最大值 m、归一化因子 l、尚未除以 l 的 value 加权和 z。处理新分数块 s 与 values v 时，新的最大值记为 m_new。

```text
m_new = max(m, max(s))
a = exp(m - m_new)
p = exp(s - m_new)
l_new = a * l + sum(p)
z_new = a * z + sum(p_j * v_j)
最终输出 = z / l
```

初始化可以取 `m=-∞,l=0,z=0`；先考虑每块至少有一个合法有限分数的情况，全被 mask 的块需要单独处理，避免 `-∞−(-∞)` 产生 NaN。

手算一次最大值变化：第一块分数 0、value=2，得到 m=0、l=1、z=2。第二块分数 ln(2)（即 exp 后等于 2 的数）、value=4，新最大值为 ln(2)，于是 a=1/2、新 p=1；l_new=1.5、z_new=5，输出为 5/1.5=10/3。直接对 [0,ln(2)] 做 Softmax 也得到 [1/3,2/3]，加权结果同样是 10/3。

旧累积量需要乘 a，因为我们更换了指数计算的参考最大值。这里的 z 是向量，而 l 是标量。这个递推把数值稳定与全局归一化结合起来，是理解 online Softmax 的关键。

### 数学等价，不意味着浮点逐 bit 相同

不同块大小和累加顺序会改变有限精度的舍入路径。实现追求相同的数学计算目标，但 FP16/BF16/FP32 下可能存在细小差异。

验证时先用小规模参考、明确容差，再检查实际模型输出和任务质量。不要把微小舍入差异直接判成模型结构变化，也不要因为一句输出“看起来正常”就忽略明显数值偏差。

Prefill 和 Decode 的形状又不同：一个可能有较多 query，另一个只含少量新 query 且历史 K/V 很长。适合某个形状的 kernel，不一定适合另一个阶段。

### 量化：节约的字节不是免费的

量化把更高精度数值映射到较小表示，通常还需要 scale，可能有 zero point 或分组信息。一个最简单的示意是 `q=round(x/scale)`，恢复近似值 `x_hat=q×scale`。真实 FP8、INT4 等格式和实现更复杂，不能用这个示意替代具体定义。

权重量化主要影响权重存储与相关读取；KV 量化影响缓存容量和历史读取。两者针对的成本不同。若瓶颈是权重读取，减少 KV 不一定解决；若长上下文缓存压力很大，只压缩权重也可能不够。

反量化、scale 读取、数据重排以及硬件支持决定实际速度。某个低 bit 格式若需要昂贵转换，可能省了显存却没有加速。必须把存储格式和执行 kernel 一起看。

### 为什么质量检查不能只看算子误差

量化会改变数值表示。某些局部误差在多层计算后可能累积，影响 logits 和生成结果。除了比较算子输出，还应在代表性任务上比较模型质量，尤其关注业务中的长上下文、特殊输入或边界样本。

与之相比，单纯改变调度顺序通常不打算改变模型的数学计算；但实际 batch 形状与浮点执行也可能导致差异。不同类型改动需要不同强度的验证，不能把“优化”当成自动保持语义的标签。

### Amdahl 定律帮你决定是否值得做

设某热点占原总时长 f，优化后自身快了 s 倍，其他部分不变。把原时长归一化为 1，新时长就是 `(1−f)+f/s`，整体加速比为它的倒数。

例如热点占 10%，自身快 2 倍，整体新时长为 `0.9+0.1/2=0.95`，只快约 1.053 倍。即使把它优化到几乎不耗时，整体极限也只有 `1/0.9≈1.111` 倍。

若热点占 70%，同样快 2 倍，整体可达到 `1/(0.3+0.35)≈1.538` 倍。相同的 kernel 成果，在不同系统里价值差异很大。

### 用这三个问题挑选你的项目

先问：瓶颈是否已被 trace 证实？再问：优化是否真的减少关键资源或关键路径？最后问：收益上限值得承担实现和维护成本吗？

练习：一个 KV 量化方案减少一半缓存，却让短上下文请求慢了 5%。参考解释包括新转换开销，以及短上下文并非 KV 读取受限。它仍可能适合另一类工作负载，但必须写出边界。
