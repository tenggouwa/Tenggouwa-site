### 从你已经会的部署工作出发

你启动一个模型服务，指定模型路径、显存利用率和最大上下文，然后发送“解释一下 KV Cache”。服务返回一段文字。你现在熟悉的是这条链路的入口和出口；这一课要打开中间的黑箱：GPU 到底对什么数据做了什么计算？

先把“模型”和“推理引擎”分开。模型描述一套计算结构，以及训练得到的权重；引擎负责把请求组织起来，安排内存、调度计算，并调用适合硬件的实现。同一个模型可以由不同引擎执行；同一个引擎也能执行不同模型。后续的定制优化，往往是在保持模型数学意义基本不变的前提下，改变执行方式。

学习时分两遍走：第一遍阅读、手算和做网页自测；第二遍运行代码、记录证据，再勾选实验验收。没有相应设备时可以继续阅读后面的课，但不要把未运行的实验记成已验证。第 1–6 课建立基础，第 7–9 课画清引擎职责，第 10–15 课补齐算子与多卡机制，第 16–18 课才集中实现真实引擎改动。

本课不要求你先学完深度学习。只需要会读 Python 变量、列表和函数。遇到一个新符号，我们先解释它表示什么，再参与计算。

### 文字进入模型之前，发生了什么

模型不能直接对汉字做矩阵乘法。Tokenizer 先把文本拆成 token，再把每个 token 映射为整数 ID。Token 可能是一段字符、一个词的片段或其他编码单元，不保证等于一个汉字，也不保证等于一个英文单词。

假设我们用一个虚构 tokenizer，把“今天适合学习”编码成 `[12, 47, 83, 9]`。这四个数只是索引：83 并不比 12 “更重要”。真实 tokenizer 的切分和 ID 由对应模型决定，这里的数字只是便于演示。

接着执行 Embedding。你可以把它看成一张有 V 行、D 列的数字表：V 是词表大小，D 是每个 token 的向量长度。ID=12 就取第 12 行。四个 ID 变成四个长度为 D 的向量，形状从 `[4]` 变为 `[4,D]`。

为什么需要向量？因为后续网络需要一组可以连续变化的数值特征。每个维度通常没有可以直接命名的人类含义；不要把它理解成“第一维代表语法，第二维代表情绪”。训练调整了表里的数字，使它们能配合后续层完成预测。

### 张量的 shape，是读模型的第一种语言

一个数叫标量，一排数叫向量，二维数组叫矩阵。张量是更一般的多维数值数组。读代码时，先看 shape，再看函数名，往往更容易理解实际发生的事。

本课采用三个常用字母：B 表示 batch 中序列数，T 表示序列长度，D 表示隐藏维度。两个请求，每个四个 token，每个 token 八个特征，就得到 `[B,T,D]=[2,4,8]`，一共有 64 个数。

| 操作 | 输入 | 输出 | 发生了什么 |
| --- | --- | --- | --- |
| Embedding | `[B,T]` 的整数 ID | `[B,T,D]` | 每个 ID 查到一个向量 |
| Linear | `[B,T,D]` | `[B,T,O]` | 每个 token 的特征维由 D 变成 O |
| reshape | `[B,T,D]` | `[B×T,D]` | 重新解释维度，不改变元素数 |
| transpose | `[T,D]` | `[D,T]` | 交换轴；通常改变视图的 stride |

注意，reshape 是否复制数据取决于原始布局，transpose 通常也不等于真的搬运全部数据。先区分逻辑形状和内存布局；到 GPU 课程我们再研究它为什么影响性能。

### 一次 Linear，逐个数字看懂

Linear 的核心是矩阵乘法。假设一个 token 的向量是 `[1,2]`，权重矩阵是：

```text
W = [[1, 0, 2],
     [0, 1, 3]]
```

第一项输出是 `1×1+2×0=1`，第二项是 `1×0+2×1=2`，第三项是 `1×2+2×3=8`，因此输出为 `[1,2,8]`。每个输出维度都是输入各维度的加权和。权重就是这些可以在训练中调整的系数。

多个 token 使用同一份 W，分别计算自己的输出。Linear 本身不会把第一个 token 和第二个 token 混起来；跨 token 的信息交换主要由下一课的 Attention 完成。

如果 X 是 `[2,4,8]`，W 是 `[8,24]`，那么 `X @ W` 就是 `[2,4,24]`。计算时可以把 X 的前两维合并成 8 行，理解为 `[8,8] × [8,24]`。这里是显式矩阵 W 的布局；PyTorch 的 `nn.Linear(8,24)` 把 weight 存成 `[24,8]`，内部使用转置，别把两种写法混为一谈。

### 从 shape 推导计算量与内存

矩阵 `[M,K] × [K,N]` 产生 M×N 个输出，每个输出大约需要 K 次乘法和 K 次加法。因此常用近似计数是 `2×M×K×N FLOPs`。FLOPs 表示浮点操作数量；FLOP/s 才是每秒处理的速率。

上面的例子取 M=2×4=8、K=8、N=24，得到约 3072 FLOPs。这里忽略了 bias 等小项。W 有 8×24=192 个参数，若每个参数用 2 bytes 保存，权重主体是 384 bytes。

如果把 B 翻倍，输入、输出和计算量翻倍，但 W 仍然只有一份。这个“更多 token 共用同一份权重”的事实，会在后面解释为什么 batch 能提高硬件利用效率。

BF16 和 FP16 都用 2 bytes，但表示数值的方式不同。BF16 的指数范围更大，FP16 的尾数精度更高；两者都不等于任意实数的精确存储。推理工程必须关心数值误差，因为改变精度或计算顺序可能改变结果。

### 将它放回一次文本生成

Embedding 的输出会经过多层 Transformer block，得到新的 `[B,T,D]` 状态。最后的输出投影把隐藏向量映射到词表大小 V，形成 logits。Logits 是尚未归一化的分数；经过 Softmax 可以变为概率，随后按 greedy（选分数最高的 token）或 sampling（按概率抽样）等规则选出下一个 token。Softmax 的计算方法放在下一课；本课先理解它把分数变成总和为 1 的概率。

选出的 token 又成为下一步的输入。这个反复“计算下一项、把它接到后面”的过程叫自回归生成。它解释了为什么生成一段 100-token 的文本，通常需要多步依赖前一步的计算，而不能随意把全部步骤同时完成。

训练会根据目标和损失调整权重；推理通常只读取固定权重。你此时要理解的是推理前向计算，不需要先从零训练一个大模型。

### 跟着运行，再解释结果

项目中的 `work/lab-venv` 若已安装 PyTorch，可以在项目根目录运行下面的代码；否则按 README 创建隔离环境。这段代码用随机数验证形状，不会生成有意义的语言。

```python
import torch

torch.manual_seed(7)
x = torch.randn(2, 4, 8)
w = torch.randn(8, 24)
y = x @ w
assert tuple(y.shape) == (2, 4, 24)
print("输出形状:", tuple(y.shape))
print("近似 FLOPs:", 2 * 2 * 4 * 8 * 24)
print("W 参数数:", w.numel())
```

先想一想：把 `B=2,T=4` 改为 `B=1,T=8`，这一次 Linear 的计算量会变化吗？参考解答是不会：两者都有 8 个输入向量，W 也没变。但整个模型的 Attention 和请求调度会区分它们，所以不能据此断言完整模型耗时相同。

再想一想：一个 7B 参数模型用 2 bytes/参数，仅权重主体约 14 GB，为什么不能保证在 14 GB 可用显存里运行？因为还有缓存、激活（前向计算中的中间张量）、workspace（算子临时工作空间）和运行时开销。参数存储估算只是其中一项。

### 这一课之后，你应该带走什么

现在看到 `x @ w`，你应能追踪输入维度、输出维度、参数数量和近似操作数。暂时不要追求理解所有层；先把“文字 → token ID → 向量 → 数值计算 → logits → 下一个 token”串起来。

还有一个问题没有回答：如果 Linear 对每个 token 独立工作，模型如何知道“它”指的是前文的哪个对象？下一课用 Attention 解释位置之间怎样交换信息。读完后回到本课下方的自测与练习，用两组手算结果作为第一份学习证据。
